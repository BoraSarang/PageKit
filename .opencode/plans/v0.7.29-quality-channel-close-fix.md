# 플랜: 품질진단 "message channel closed" 오류 수정 (v0.7.29)

## 증상
- 수동 "분석 시작" 클릭 → `분석 실패: A listener indicated an asynchronous response by returning true, but the message channel closed before a response was received`
- SW 로그: `[QUALITY] 분석 실패 tab=... code=E-CHR-PERM-1002`

## 원인 진단
`content/quality-analyzer.js`의 메시지 리스너가 `return true`(비동기 응답 예약) 후
promise 체인에 **catch 가 없음**:

```
runQualityAnalysis(...).then(async (result) => { ... sendResponse(...) });
// ← reject 시 sendResponse 영영 안 불림 → 채널 닫힘 → 위 영어 오류로 발현
```

v0.7.27~28에서 추가된 아래 코드들이 리스너 체인 **최상단**에 있어
런타임 오류 발생 시 전체가 무응답이 됩니다:
1. `waitForSettle()` — load 이벤트 대기(최대 5초) + 네트워크 정지 폴링
2. `const th = {...DEFAULT_QUALITY_CONFIG.thresholds, ...(config?.thresholds || {})}` + 최소점수 미달 검사 루프
3. `collectFrameQuality(result)` — iframe 수집(3s 타임아웃 내부)

또한 분석 총 소요가 길어져(정지대기+모듈+프레임 ≈ 10~20초) 그 사이 페이지 이동/리로드 시
컨텐츠 컨텍스트 소멸로도 동일 오류가 납니다.

## 수정 내용 (content/quality-analyzer.js)

### 1. 메인 리스너 — 어떤 경우에도 응답 보장 (핵심)
```javascript
if (message?.type === 'pk.quality.analyze') {
  if (window !== window.top) return false;
  runQualityAnalysis(message.payload?.modules)
    .then(async (result) => {
      await collectFrameQuality(result);
      rebuildFlatIssues(result);
      sendResponse({ ok: true, data: result });
    })
    .catch((e) => {
      DebugLogger.error('QUALITY', `분석 파이프라인 오류: ${e.message}`);
      try { sendResponse({ ok: false, error: `분석 중 오류가 발생했습니다: ${e.message}` }); } catch {}
    });
  return true;
}
```
- 기존 미사용 변수 `enabledModules` 제거

### 2. waitForSettle 실패는 치명적이지 않음 — best-effort화
```javascript
try { await waitForSettle(); } catch { /* 정지 감지 실패 허용 */ }
```

### 3. 최소점수 미달 검사 블록 try/catch 래핑
- 어노테이션은 부가 정보일 뿐 — 실패해도 분석은 계속되어야 함
- 개별 이슈 push 실패 시 DebugLogger.warn 후 계속

### 4. iframe 분석 브랜치도 .catch 추가 (위생)
```javascript
runQualityAnalysis(...).then(result => { postMessage... }).catch(() => {});
```
(부모 쪽 3초 타임아웃이 이미 있으나 무응답 rejection 방지)
